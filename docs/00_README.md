# ICONIXプロセス設計書シリーズ 目次

Webシステム開発（専門学校の演習・卒業制作）で、ICONIXプロセスに沿って設計書を作成するためのルール集。
設計書（ドメインモデル・ユースケース・ロバストネス図・シーケンス図・クラス図）を作成・レビューするときは、該当する回のファイルを参照すること。

参考文献：『ユースケース駆動開発実践ガイド　オブジェクト指向分析からSpringによる実装まで』（ダグ・ローゼンバーグ／マット・ステファン）

## グループ統一ルール（早見表）

| 対象 | ルール | 詳細 |
| --- | --- | --- |
| ドメインモデルのクラス名 | 英単語の小文字＋アンダースコア区切り（`order_detail`）。日本語・パスカルケース・ローマ字は不可 | 01 |
| is-a／has-a | is-a＝実線＋三角、has-a＝実線＋ひし形（ひし形は全体側）。単純な矢印だけは不可 | 01 |
| ドメインモデルに書く内容 | クラス名のみ。属性・メソッド・View/Controllerは書かない | 01 |
| ユースケース名 | 必ず「●●を△△する」形式 | 02 |
| ユースケース間の関係 | 《invokes》《precedes》のみ。《include》《extend》は使わない | 02 |
| ユースケース記述の順序 | 名前 → アクター → 事前条件 → **事後条件（事前条件の直下）** → 基本フロー → 代替フロー | 02 |
| フローの番号 | 基本フロー＝①②③…、代替フロー＝③a.（分岐元＋枝番）。1文＝1アクション | 02 |
| ロバストネス図の命名 | 日本語。バウンダリ「●●画面」／コントローラ「●●を●●する」／エンティティ「●●」。英単語（実装名）は書かない | 03 |
| ロバストネス図の接続 | バウンダリ↔エンティティ直結は不可。アクターはバウンダリ経由 | 03 |
| ロバストネス図の線 | 基本フロー＝実線、代替フロー＝破線＋［条件］ラベル | 03 |
| シーケンス図の範囲 | 活性区間・loopは書かない。矢印＋必要に応じてaltのみ。メッセージ名は日本語ラベルでよい | 04 |
| GET／POST | ブラウザ↔view間のみ。view→Entityには使わない | 04 |
| リダイレクト | 「呼び出し元へ戻す（302）」→「新しいリクエスト」の2段階で描く | 04 |
| クラス図 | 可視性（`+ - # ~`）を設定、関連の両端に多重度を書く。シーケンス図のメソッドを漏れなく反映 | 05 |

## 図（Mermaid）について

元資料の図は画像だったため、このmd版では資料内のテキスト記述から書き起こしたMermaid図で代替している箇所がある（03・04・05）。
01の「注文システムのドメインモデル図」は元の図の内容がテキストに無いため、図は含めていない。
