# ④ シーケンス図

作成ルール：[docs/04_シーケンス図の書き方.md](../docs/04_シーケンス図の書き方.md)

本演習の範囲に合わせ、活性区間・loopフレームは記述しない。GET／POSTはアクター（ブラウザ）↔view間のみに用い、view→モデル間の内部呼び出しには使わない。リダイレクトは「呼び出し元へ戻す（302）→新しいリクエスト」の2段階で描く。

viewの参加者名は、[03_ロバストネス図.md](03_ロバストネス図.md)の各コントローラ（●●を●●する）に対応するDjangoのview関数を指す。モデル名は[05_クラス図.md](05_クラス図.md)で確定する実装クラス名（`Activity`／`Certification`／`Skill`／`Tag`、管理者はDjango標準の`User`）を用いる。

## 1. プロフィールを閲覧する

```mermaid
sequenceDiagram
    actor 訪問者
    participant profile_view
    participant Activity
    participant Certification
    participant Skill

    訪問者->>profile_view: GET（プロフィール画面を表示する）
    profile_view->>Activity: 一覧を取得する
    Activity-->>profile_view: 一覧を返却
    profile_view->>Certification: 一覧を取得する
    Certification-->>profile_view: 一覧を返却
    profile_view->>Skill: 一覧を取得する
    Skill-->>profile_view: 一覧を返却
    profile_view-->>訪問者: 表示する
```

## 2. 管理者としてログインする

```mermaid
sequenceDiagram
    actor 管理者
    participant login_view
    participant dashboard_view
    participant User

    管理者->>login_view: GET（ログイン画面を表示する）
    login_view-->>管理者: 表示する
    管理者->>login_view: POST（ユーザー名・パスワード）
    alt 認証成功の場合
        login_view->>User: 認証情報を照合する
        User-->>login_view: 認証成功
        login_view-->>管理者: リダイレクト（302）
        管理者->>dashboard_view: GET（自動的に新しいリクエスト）
        dashboard_view-->>管理者: 管理画面を表示する
    else 認証失敗の場合
        login_view->>User: 認証情報を照合する
        User-->>login_view: 認証失敗
        login_view-->>管理者: エラーメッセージを表示する
    end
```
